# Обновления Textora через GitHub Releases

## Что внедрено

Sparkle 2.10.0, **Check for Updates…** в меню и Settings → System,
настройка автоматической проверки. Sparkle спрашивает разрешение на фоновые
проверки; стандартный интервал — сутки. Установка требует действия пользователя.
Настройку проверок хранит сам Sparkle.

Постоянный адрес ленты:
`https://github.com/MasterHrust/Textora/releases/latest/download/appcast.xml`.
Каждый стабильный Latest-релиз должен содержать **Textora.dmg и appcast.xml**.
Ссылки на DMG внутри ленты привязаны к конкретному тегу. Сервер и Pages не нужны.

## Один раз перед первой публикацией

Команды выполняются из каталога macOS-приложения.

1. Загрузить зависимость и инструменты:

   ```bash
   xcodebuild -resolvePackageDependencies -project Textora.xcodeproj -scheme Textora -clonedSourcePackagesDirPath .deriveddata-updates/SourcePackages
   ```

2. Создать ключ в macOS Keychain:

   ```bash
   .deriveddata-updates/SourcePackages/artifacts/sparkle/Sparkle/bin/generate_keys --account Textora
   ```

   Вставить напечатанный **публичный** ключ в `SUPublicEDKey` файла
   `Sources/Info.plist`. Публичный ключ Textora уже настроен для версии 1.1;
   на текущем Mac закрытый ключ находится в Keychain под аккаунтом `Textora`.
   Эти шаги нужны только при первоначальной настройке; на другом Mac следует
   импортировать сохранённый ключ, а не создавать замену.
   Закрытый ключ остаётся в Keychain. Сохранить резервную копию в защищённом
   хранилище вне репозитория; экспорт поддерживается через `generate_keys -x`.
   Не генерировать новый ключ для каждого релиза.

3. Проверить Developer ID signing и нотариализацию приложения вместе со
   встроенным Sparkle. Подпись обновления не заменяет подпись Apple и
   нотариализацию. Сохранять bundle ID `com.textora.app` и команду Apple Developer.
4. Проверить доступность релизов без входа в GitHub. Для приватного репозитория
   нужны публичные файлы обновлений и соответствующие URL.

## Каждый следующий релиз

1. В `Sources/Info.plist` увеличить `CFBundleVersion` (1 → 2 → 3…), а
   `CFBundleShortVersionString` выставить в пользовательскую версию (например 1.1).
   Номер сборки должен превышать все ранее опубликованные номера.
2. Собрать Release, подписать Developer ID, нотариализовать и подготовить DMG.
   Образ должен содержать новую `Textora.app` со встроенным Sparkle.framework.
   При упаковке сохранять symlinks и executable permissions.
3. Подготовить файлы в новом каталоге:

   ```bash
   bash Scripts/prepare-update.sh v1.1 Textora.dmg /tmp/textora-v1.1
   ```

   Скрипт использует ключ `Textora` из Keychain и генерирует appcast без delta
   updates. Если инструменты расположены иначе, задать `SPARKLE_BIN`.
   Тег должен соответствовать версии внутри DMG: проверить перед публикацией.
   Скрипт не собирает, не нотариализует и не публикует приложение.
4. Создать **draft** GitHub Release с тегом `v1.1`, добавить описание изменений,
   загрузить **оба файла из выходного каталога**. Проверить в XML номер сборки,
   версию, минимальную macOS, подпись и ссылку на DMG. Опубликовать стабильный
   релиз с отметкой **Latest**. Текст GitHub release notes автоматически в окно
   Sparkle не копируется; ссылка на страницу релиза включена в appcast.
5. Проверить постоянный URL ленты и скачивание DMG по ссылке из неё.
   Опубликованный DMG не заменять: подпись соответствует точным байтам файла.
   Для исправления выпустить следующую сборку.

## Проверка перед первым публичным выпуском

Использовать две подписанные и нотариализованные сборки с одинаковым bundle ID,
публичным ключом и возрастающими номерами. Для репетиции задать отдельную
HTTPS-ленту через `SUFeedURL` в тестовых сборках.

- Установить старую сборку в Applications и вызвать Check for Updates.
- Проверить скачивание, установку, перезапуск и номер новой версии.
- Проверить настройки, доступ к API-ключам, Accessibility и запуск при входе.
- Проверить отсутствие обновлений на новой версии и ошибку при недоступной сети.
- Проверить сохранение выбора автоматических проверок после перезапуска.
- Проверить отказ от пакета, изменённого после подписи.

Полную установку нельзя проверить одной неподписанной локальной сборкой.
Первую версию со Sparkle существующие пользователи устанавливают вручную.
